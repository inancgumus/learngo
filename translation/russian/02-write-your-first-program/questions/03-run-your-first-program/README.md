## В чём разница между `go build` и `go run`?
1. `go run` только компилирует программу; а `go build` и компилирует, и запускает её.
2. `go run` и компилирует, и запускает программу; а `go build` только компилирует её. *CORRECT*

> **1:** На самом деле наоборот.
>
>
> **2:** `go run` компилирует вашу программу и кладёт её во временный каталог. Затем он запускает скомпилированную программу оттуда.
>
>


## Go сохраняет скомпилированный код в каталог. Как называется этот каталог?
1. Тот же каталог, где вы вызываете `go build` *CORRECT*
2. Каталог $GOPATH/src
3. Каталог $GOPATH/pkg
4. Во временный каталог.

> **2:** Там лежат только исходные файлы Go
>
>
> **3:** Go кладёт туда ваш код только при вызове `go install`.
>
>


## Что верно для времени выполнения (runtime)?
1. Оно наступает, когда ваша программа начинает работать на компьютере *CORRECT*
2. Оно наступает, пока ваша программа компилируется


## Что верно для времени компиляции (compile-time)?
1. Оно наступает, когда ваша программа начинает работать на компьютере
2. Оно наступает, пока ваша программа компилируется  *CORRECT*


## Когда программа на Go может напечатать сообщение в консоль?
1. Пока она компилируется.
2. Пока она выполняется (после времени компиляции). *CORRECT*
3. Пока она выполняется (внутри времени компиляции).

> **1:** На этапе компиляции программа не может печатать сообщение. На этом этапе она буквально мертва.
>
>
> **2:** Верно. Это единственное время, когда ваша программа может взаимодействовать с компьютером и дать ему команду напечатать сообщение в консоль.
>
>
> **3:** Выполнение может происходить только после времени компиляции
>
>
